Catálogo estandares

estandar_tiempo

tabla nueva

Responsabilidad

Meta de tiempos operativos por tipo de equipo: disponibilidad_meta_pct, utilizacion_meta_pct y demora_max_pct. Con vigente_desde y estado VIGENTE/HISTORICO.

Por qué

Las metas cambian con el tiempo (negociaciones, mejoras de flota). El campo vigente_desde junto con el índice único parcial garantiza que solo exista un estándar activo por tipo de equipo y empresa; los anteriores pasan a HISTORICO sin borrarse.

Catálogo estandares

estandar_productividad

tabla nueva

Responsabilidad

Meta de productividad por actividad (barrenación, rezagado, acarreo, anclaje, zarpeo, relleno) y opcionalmente por tipo de equipo. La unidad es uno de: TON_HORA, METRO_HORA, TON_GUARDIA, METRO_GUARDIA.

Por qué

Diferentes actividades se miden en unidades distintas (toneladas por hora en acarreo, metros por guardia en barrenación). Separar la tabla de productividad de la de tiempos evita columnas nulas y hace que cada meta sea específica a su actividad con su propia vigencia.

Código SQL

DDL real (PostgreSQL)

Esquema del archivo 09_estandares.sql. Pasa el cursor sobre las columnas resaltadas para ver su explicación.

estandares / estandar_tiempo.sql (catálogo — metas de tiempos por tipo de equipo) 
CREATE TABLE estandares.estandar_tiempo (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  id_empresa UUID NOT NULL,
  id_tipo_equipo UUID NOT NULL,
  disponibilidad_meta_pct NUMERIC(6,2),
  utilizacion_meta_pct NUMERIC(6,2),
  demora_max_pct NUMERIC(6,2),
  vigente_desde DATE NOT NULL,
  estado TEXT NOT NULL DEFAULT 'VIGENTE',
  creado_en TIMESTAMPTZ NOT NULL DEFAULT now(), creado_por_usuario_id UUID,
  actualizado_en TIMESTAMPTZ NOT NULL DEFAULT now(), actualizado_por_usuario_id UUID,
  eliminado_en TIMESTAMPTZ, eliminado_por_usuario_id UUID,
  CONSTRAINT ck_estandar_tiempo_estado CHECK (estado IN ('VIGENTE','HISTORICO')),
  CONSTRAINT fk_estandar_tiempo_empresa FOREIGN KEY (id_empresa) REFERENCES gobierno.empresa(id) ON DELETE RESTRICT,
  CONSTRAINT fk_estandar_tiempo_tipo_equipo FOREIGN KEY (id_tipo_equipo) REFERENCES catalogos.tipo_equipo(id) ON DELETE RESTRICT
);
CREATE UNIQUE INDEX uq_estandar_tiempo ON estandares.estandar_tiempo (id_empresa, id_tipo_equipo, vigente_desde) WHERE eliminado_en IS NULL;
estandares / estandar_productividad.sql (catálogo — metas de productividad por actividad) 
CREATE TABLE estandares.estandar_productividad (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  id_empresa UUID NOT NULL,
  id_actividad UUID NOT NULL,
  id_tipo_equipo UUID,
  unidad TEXT NOT NULL,
  valor_meta NUMERIC(14,4) NOT NULL,
  vigente_desde DATE NOT NULL,
  estado TEXT NOT NULL DEFAULT 'VIGENTE',
  creado_en TIMESTAMPTZ NOT NULL DEFAULT now(), creado_por_usuario_id UUID,
  actualizado_en TIMESTAMPTZ NOT NULL DEFAULT now(), actualizado_por_usuario_id UUID,
  eliminado_en TIMESTAMPTZ, eliminado_por_usuario_id UUID,
  CONSTRAINT ck_estandar_prod_unidad CHECK (unidad IN ('TON_HORA','METRO_HORA','TON_GUARDIA','METRO_GUARDIA')),
  CONSTRAINT ck_estandar_prod_estado CHECK (estado IN ('VIGENTE','HISTORICO')),
  CONSTRAINT fk_estandar_prod_empresa FOREIGN KEY (id_empresa) REFERENCES gobierno.empresa(id) ON DELETE RESTRICT,
  CONSTRAINT fk_estandar_prod_actividad FOREIGN KEY (id_actividad) REFERENCES catalogos.actividad(id) ON DELETE RESTRICT,
  CONSTRAINT fk_estandar_prod_tipo_equipo FOREIGN KEY (id_tipo_equipo) REFERENCES catalogos.tipo_equipo(id) ON DELETE RESTRICT
);
CREATE UNIQUE INDEX uq_estandar_prod ON estandares.estandar_productividad (id_empresa, id_actividad, vigente_desde) WHERE eliminado_en IS NULL;

Nota: id_tipo_equipo es opcional en estandar_productividad: permite definir una meta general por actividad y otra más específica por tipo de equipo dentro de la misma actividad.

Preguntas frecuentes

Decisiones de diseño

¿Por qué las metas son catálogos con vigente_desde y no un solo valor fijo?
Las metas operativas cambian: una renovación de flota eleva la disponibilidad esperada, una renegociación sindical ajusta la productividad. Con vigente_desde cada cambio genera un nuevo registro (estado VIGENTE) y archiva el anterior (estado HISTORICO), conservando el historial completo para auditoría y comparativas de periodos pasados. Sin este mecanismo sería imposible responder "¿cuál era la meta en enero?" al revisar los indicadores de ese mes.
¿Cómo se compara el real contra el estándar?
A través de una vista o consulta analítica que une las tablas de producción con la meta vigente en la fecha del parte. Para tiempos: se calculan los minutos disponibles, utilizados y de demora desde demora_equipo y los horómetros del parte, y se expresan como porcentaje; luego se comparan contra disponibilidad_meta_pct, utilizacion_meta_pct y demora_max_pct. Para productividad: se suman toneladas o metros de los eventos de detalle y se dividen entre las horas del turno, comparando el resultado contra valor_meta en la unidad correspondiente.
¿Qué diferencia hay entre disponibilidad y utilización?
Disponibilidad mide cuánto tiempo el equipo estuvo en condiciones de operar (sin falla mecánica) respecto al tiempo total del turno. Utilización mide cuánto del tiempo disponible se usó efectivamente en trabajo productivo. Un equipo puede tener alta disponibilidad (pocas fallas) pero baja utilización (muchas demoras operativas). La demora_max_pct complementa la foto: limita el porcentaje de tiempo que se puede perder en demoras antes de considerarse fuera de estándar. Los tres indicadores juntos forman el OEE (Overall Equipment Effectiveness) simplificado para el dominio minero.
¿Por qué estandar_productividad tiene id_tipo_equipo opcional?
Porque algunas actividades tienen una meta única sin importar el equipo (por ejemplo, relleno = 20 m³/h independientemente de la máquina), mientras que otras pueden diferenciarse (rezagado con scooptram grande vs pequeño). La columna es NULL cuando la meta aplica a todos los equipos de la actividad; cuando no es NULL, la meta es específica para ese tipo de equipo. El índice único parcial uq_estandar_prod garantiza que no existan dos metas vigentes para la misma combinación empresa + actividad + fecha de inicio.
